# Qwen-Image-2512 Character LoRA Training Pipeline

**Date**: 2026-03-26
**Status**: Draft

## Overview

A K3s-deployed pipeline for training character-specific LoRA weights on Qwen-Image-2512 (20B MMDiT). The LoRA encodes a real person's full-body identity (face, proportions, distinguishing marks) so they can be rendered photorealistically in arbitrary poses, settings, and outfits via text prompts alone.

## Requirements

### Functional

- **Character identity preservation**: Face, body proportions, skin tone, and distinguishing marks (tattoos, scars, birthmarks) remain consistent across all generations.
- **Pose control via text**: The trained LoRA responds to natural language pose descriptions (e.g. "sitting cross-legged," "running through a field," "standing with arms raised").
- **Setting control via text**: Backgrounds and environments are fully controllable through prompts, independent of character identity.
- **Outfit control via text**: Clothing is not baked into the LoRA -- the model follows prompt instructions for what the character wears.
- **Photorealistic output**: Generated images should be indistinguishable from photographs, consistent with Qwen-Image-2512's native capabilities.

### Non-Functional

- Training runs as K3s Jobs on an NVIDIA GB10 (ARM64 Blackwell, 128GB unified memory).
- The pipeline requires only photos as input -- captioning is automated.
- The resulting LoRA weights are portable (standard safetensors format, usable in diffusers or ComfyUI).

- PyTorch 2.10.0a0 with native ARM64 SBSA + Blackwell support
- cuDNN 9.15, NCCL 2.27.7, TransformerEngine 2.8

## Captioning

### Strategy

Each training image gets a detailed natural language caption that separates identity (anchored to the trigger word) from variable attributes (pose, clothing, setting). This teaches the model:
- Trigger word `ohwx` = this person's physical identity
- Everything else = controllable via prompt

### Implementation

A Python script (`caption.py`) that:
1. Iterates over all images in `/dataset/images/`
2. For each image, sends a request to the user's self-hosted vLLM endpoint (OpenAI-compatible API)
3. Uses a system prompt that instructs the VL model to produce structured captions
4. Writes the caption to `/dataset/captions/<image_stem>.txt`

**Configuration via environment variables:**

| Env Var | Required | Description |
|---|---|---|
| `VLM_API_URL` | Yes | Base URL of the vLLM endpoint (e.g. `http://vlm-service.default.svc:8000/v1`) |
| `VLM_MODEL_NAME` | No | Model name for the API request (default: auto-detect) |
| `TRIGGER_WORD` | No | Trigger word to inject (default: `ohwx`) |
| `IMAGE_DIR` | No | Path to images (default: `/data/dataset/images`) |
| `CAPTION_DIR` | No | Path to write captions (default: `/data/dataset/captions`) |

### System Prompt for Captioning

The VL model receives a system prompt that produces captions in this structure:

```
A photo of ohwx. [Physical description matching the person -- kept constant].
[Pose and expression -- varies per image].
[Clothing and accessories -- varies per image].
[Setting, background, and lighting -- varies per image].
```

Example output:
```
A photo of ohwx, a man with short dark brown hair, light skin, brown eyes,
and a small scar above the left eyebrow. He is sitting on a wooden bench
with his legs crossed, smiling with teeth showing. He wears a navy blue
t-shirt and khaki shorts. The setting is an outdoor park with green trees
and dappled sunlight filtering through the canopy.
```

The system prompt instructs the VL model to:
- Always begin with `A photo of {trigger_word}`
- Describe the person's fixed physical traits (face shape, eye color, skin tone, hair, distinguishing marks)
- Separately describe pose, expression, clothing, and setting
- Use natural English, no tags or structured formats
- Not mention camera settings or photography terminology

### Caption Review

After the captioning Job completes, the user should review a sample of captions to verify:
- The trigger word is consistently present
- Physical descriptions are accurate and consistent across images
- Pose/clothing/setting descriptions vary appropriately

The user can edit captions manually before running training. The captions are plain text files alongside the images.

## Training Configuration

### SimpleTuner Settings

The training uses Dreambooth-LoRA methodology: the trigger word binds the person's identity into the LoRA weights, while regularization images prevent the model from forgetting how to generate other people and follow diverse prompts.

**Core config:**

| Parameter | Value | Rationale |
|---|---|---|
| `model_family` | `qwen_image` | Qwen-Image-2512 model family |
| `pretrained_model_name_or_path` | `/data/models/Qwen-Image-2512` | Local path on PVC |
| `base_model_precision` | `bf16` | Full precision -- 128GB unified, no quantization |
| `training_type` | `lora` | LoRA (not full fine-tune) |
| `lora_rank` | 64 | High rank for capturing full-body detail at all scales |
| `lora_alpha` | 64 | Alpha = rank for unit scaling |
| `learning_rate` | 3e-5 | Conservative for rank 64 |
| `lr_scheduler` | `constant_with_warmup` | Stable training |
| `lr_warmup_steps` | 100 | Gentle warmup |
| `optimizer` | `adamw-bf16` | Native bf16 optimizer |
| `train_batch_size` | 4 | Fits comfortably in 128GB unified |
| `gradient_accumulation_steps` | 4 | Effective batch size 16 |
| `max_train_steps` | 3000 | Target range for 40-80 images |
| `mixed_precision` | `bf16` | Mandatory for Qwen-Image |
| `gradient_checkpointing` | `true` | Reduces peak memory for larger batches |
| `max_grad_norm` | 0.01 | Prevents training instability (Qwen-Image specific) |

### Dataset Preparation Guidelines

**Training images (provided by user):**
- 40-80 high-quality photos of the subject
- Distribution: ~15 face closeups, ~15 upper body, ~25 full body, ~10 various angles
- Diverse lighting conditions (indoor, outdoor, overcast, direct sun)
- Diverse backgrounds (the more varied, the better -- prevents background leaking into identity)
- Diverse clothing (prevents outfit from becoming part of identity)
- Diverse poses (standing, sitting, walking, gesturing)
- Minimum resolution: 512x512, ideally 1024+ on the longest edge
- Format: JPEG or PNG
- No heavy filters, watermarks, or text overlays
- No other people in the frame (or crop to isolate the subject)

**Regularization images (pre-populated by user):**
- 1000-5000 generic photos of people (not the subject)
- Recommended source: `bghira/pseudo-camera-10k` from HuggingFace
- Purpose: prevents the model from associating all person-related prompts with the subject
- These do not need captions (SimpleTuner can use a class prompt like `"a photo of a person"`)

## Usage Flow

1. Build and push the container image to a registry accessible by K3s.
2. Apply `pvc.yaml` to create the storage.
3. Copy photos to `/data/dataset/images/` on the PVC (via a temporary pod or direct host access).
4. Copy regularization images to `/data/dataset/regularization/images/`.
5. Download Qwen-Image-2512 to `/data/models/Qwen-Image-2512/` (via `huggingface-cli download`).
6. Apply `caption-job.yaml` -- wait for completion, review captions. (vLLM must be running.)
7. **Scale down vLLM**: `kubectl scale deployment <vllm-deployment> --replicas=0`
8. Apply `train-job.yaml` -- monitor training via logs, review validation samples.
9. **Scale vLLM back up**: `kubectl scale deployment <vllm-deployment> --replicas=1`
10. Retrieve the LoRA from `/data/output/lora_weights/`.

## Inference (Out of Scope)

The resulting LoRA is a standard PEFT safetensors file. It can be loaded in:
- **diffusers**: `pipe.load_lora_weights("/path/to/lora")`
- **ComfyUI**: Load as a standard LoRA node with Qwen-Image-2512 as base
- **Any framework** supporting PEFT LoRA for diffusion transformers

Example inference prompt:
```
A photo of ohwx wearing a black suit and tie, standing in front of
a cathedral at golden hour, looking directly at the camera with a
confident expression. Cinematic lighting, shallow depth of field.
```

## Risks and Mitigations

| Risk | Likelihood | Mitigation |
|---|---|---|
| NGC 25.11 image lacks sm_100 kernels for specific ops | Low | Fall back to 25.08; or build custom ops with `TORCH_CUDA_ARCH_LIST=10.0` |
| bitsandbytes doesn't ship sm_100 binaries | N/A | Not using quantization -- 128GB unified memory runs full bf16 |
| flash-attn compilation fails on ARM64 | Medium | NGC container includes optimized attention; skip flash-attn pip install |
| Training overfits (character is rigid, ignores pose prompts) | Medium | Regularization data + caption dropout=0 + diverse training images |
| Trigger word bleeds (model generates subject without trigger) | Low | Rare trigger word `ohwx` + strong regularization |
| Captions are inaccurate or inconsistent | Medium | Review step after captioning Job before starting training |
| SimpleTuner version incompatibility with NGC PyTorch | Low | Pin SimpleTuner to tested release; test in image build |
